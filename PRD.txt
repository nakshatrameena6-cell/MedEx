<h2>2. Problem Context (preserved from the problem statement)</h2>
<p>Medicines flow <strong>Medical Services Corporation → District warehouse → CHC/Block hospital → PHC → Sub-centre/ANM → Patient</strong>. Health is a state subject, so every state runs its own chain and data.</p>
<p><strong>Failures:</strong> late or paper-based reporting; demand guessed rather than forecast; surplus in one district while another stocks out; roads and demand shock during dengue season, floods and cyclones; siloed systems; states cannot pool raw data.</p>

<h2>6. Multi-Agent Architecture</h2>
<p>Adapted from the 8-agent PRYSM orchestration into seven health-supply agents under one orchestrator. Every agent output passes through the review queue (Section 9) where a decision is required.</p>
<pre><code>AushadhiGrid Orchestrator (Cloud Run)
 |
 +-- [1] Capture Agent        --&gt; voice/photo/text -&gt; structured stock, beds, attendance
 +-- [2] Forecast Agent       --&gt; PHC x drug demand, 2-8 weeks, confidence range
 +-- [3] Risk Agent           --&gt; days-of-cover, stock-out probability, R/A/G
 +-- [4] Redistribution Agent --&gt; transfer proposals under constraints
 +-- [5] Alert Agent          --&gt; escalation + multilingual briefs (WhatsApp/SMS/voice)
 +-- [6] Copilot Agent        --&gt; NL questions, scenario parsing, explanations
 +-- [7] Governance Agent     --&gt; validation, anomaly flags, audit log, drug-name mapping
 |
 All outputs --&gt; Human Review Queue --&gt; Approve | Reject | Modify | Escalate
</code></pre>
<table>
<thead>
<tr>
<th>Agent</th>
<th>Tech</th>
<th>Confidence handling</th>
</tr>
</thead>
<tbody>
<tr>
<td>Capture</td>
<td>Speech-to-Text, Gemini (text + vision), drug master match</td>
<td>Rows under 85% go to user confirmation</td>
</tr>
<tr>
<td>Forecast</td>
<td>Vertex AI / Python model, federated</td>
<td>Always outputs P10-P90 range</td>
</tr>
<tr>

<td>Shows contributing factors</td>

<h2>7. Innovation Highlights (mapped to the 20 ideas)</h2>
<ol>
<li><strong>Federated demand forecasting</strong> across state nodes; only weights leave a state (idea 1).</li>
<li><strong>Outbreak-aware features</strong>: rainfall, temperature, water-body satellite signal, past cases (2).</li>
<li><strong>Days-of-cover stock-out score</strong> with confidence range (3).</li>
<li><strong>Equity-weighted redistribution</strong>: tribal, remote and flood-prone PHCs get priority weight so the optimizer does not favour easy-to-serve areas (4, 17).</li>
<li><strong>Explainable transfers</strong>: each recommendation carries a plain-language &quot;why&quot; from Gemini (4, 12).</li>
<li><strong>Voice-first and photo-first capture</strong> in Indian languages (6, 7).</li>
<li><strong>Emergency scenario simulator</strong> (5).</li>
<li><strong>Expiry-aware transfers</strong>: short-shelf-life batches move first (10).</li>
<li><strong>Anomaly and leakage flags</strong> with auditor reasons (11).</li>
<li><strong>Supply Resilience Score</strong> per district, week-over-week drift alert (adapted from PRYSM's compliance-drift metric).</li>
<li><strong>Supply Evidence Graph</strong> (adapted from PRYSM's audit graph): Warehouse ↔ Transfer ↔ PHC ↔ Stock snapshot ↔ Alert, so every unit moved is traceable.</li>
<li><strong>Immutable audit log</strong> and human-in-the-loop on all transfers.</li>
<li><strong>Config-driven rule DSL</strong> so states can change thresholds without code deployment.</li>
<li><strong>BRICS-ready design</strong>: language packs and drug-ontology packs as configuration (rule 04).</li>
</ol>

<h2>8. Risk Intelligence Engine</h2>
<p><strong>Days of cover</strong> = usable stock ÷ forecast daily demand (P50). A conservative view uses the P90 demand.</p>
<p><strong>Status rule (configurable):</strong></p>
<table>
<thead>
<tr>
<th>Status</th>
<th>Condition</th>
</tr>
</thead>
<tbody>
<tr>
<td>Red</td>
<td>cover &lt; supply lead time + safety buffer</td>
</tr>
<tr>
<td>Amber</td>
<td>cover &lt; 2 × lead time</td>
</tr>
<tr>
<td>Green</td>
<td>otherwise</td>
</tr>
</tbody>
</table>
<p><strong>Priority Score</strong> (used to sort the alert queue):</p>
<pre><code>Priority = P(stock-out within lead time)
         × Drug Criticality (1-5)
         × Population Served (normalised)
         × Vulnerability Weight (1.0-2.0)
         × Emergency Multiplier (1.0-1.5)
</code></pre>
<p>Example: ORS at a flood-prone tribal PHC, 5 days of cover, 9-day lead time, P(stock-out) 0.82, criticality 4, vulnerability 1.8 → top of the district queue.</p>
<p><strong>Resilience Score</strong> (0-100 per district): weighted share of PHC × critical-drug pairs that are green, minus penalties for late reporting and expiring stock. Tracked weekly; a drop of more than 5 points raises an alert.</p>

<h2>9. Rule Engine and Human-in-the-Loop</h2>

<pre><code class="language-json">{
  &#34;rule_id&#34;: &#34;STOCKOUT_RED_ESSENTIAL&#34;,
  &#34;domain&#34;: &#34;stock&#34;,
  &#34;condition&#34;: &#34;drug.is_essential AND cover_days &lt; lead_time_days + safety_buffer&#34;,
  &#34;severity&#34;: &#34;HIGH&#34;,
  &#34;exposure&#34;: &#34;forecast_daily_demand * lead_time_days - stock_qty&#34;,
  &#34;explanation&#34;: &#34;Projected to run out before the next delivery can arrive.&#34;,
  &#34;action&#34;: &#34;Generate transfer proposal; notify Block MO and DHO.&#34;,
  &#34;escalate_after_hours&#34;: 24
}
</code></pre>

<h2>10. Federated Learning Design</h2>
<p><strong>Prototype:</strong> three simulated state nodes (for example Tamil Nadu, Bihar, Maharashtra), each with its own dataset and its own BigQuery dataset. State nodes train locally and share only weights.</p>
<p>Round flow: coordinator publishes global model → each node trains locally → nodes return weight updates (optionally clipped with noise) → coordinator applies data-weighted federated averaging → new version validated and stored in the model registry.</p>
<table>
<thead>
<tr>
<th>Design choice</th>
<th>Decision</th>
</tr>
</thead>
<tbody>
<tr>
<td>Model</td>
<td>Small model suited to weight averaging (e.g. Poisson/linear or small MLP on lag, seasonality, weather, footfall features)</td>
</tr>
<tr>
<td>Personalisation</td>
<td>Global base plus light per-state adjustment layer</td>
</tr>
<tr>
<td>Proof for judges</td>
<td>Chart: a data-sparse state's forecast error (MAPE) falls after joining federation versus training alone</td>
</tr>
<tr>
<td>Cross-state stock sharing</td>
<td>Only aggregated facts (drug, quantity range, warehouse) cross states, and only in emergency mode</td>
</tr>
</tbody>
</table>
<p><strong>Honesty note:</strong> the prototype simulates federation on one project with separate datasets. Production would use separate state cloud projects and a secure aggregation service.</p>

<h2>12. Redistribution Optimizer</h2>
<p>Transportation-style optimisation (OR-Tools). It is operations research, not ML, and the pitch should say so.</p>
<ul>
<li><strong>Decision variable:</strong> quantity of drug <em>d</em> moved from donor <em>i</em> to PHC <em>j</em>.</li>
<li><strong>Minimise:</strong> transport cost and delay + λ × priority-weighted unmet demand + expiry-waste penalty.</li>
<li><strong>Constraints:</strong> donor keeps a safety buffer (e.g. ≥ 14 days cover); vehicle capacity; batch expiry longer than transit time plus expected use time; road-accessibility flag (Maps travel time, with a manual &quot;road cut&quot; toggle in the demo).</li>
<li><strong>Output:</strong> ranked proposals showing quantity, source, ETA, cost, donor cover remaining, and Gemini's plain-language reason.</li>
</ul>
