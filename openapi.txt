    ## Conventions
    - Base path is `/api/v1`. All bodies are JSON unless stated (capture uploads are `multipart/form-data`).
    - Timestamps are ISO-8601 UTC (`2026-09-29T06:30:00Z`). Dates are `YYYY-MM-DD`.
    - `confidence` and probabilities are numbers from 0 to 1. Cover is measured in days.
    - Quantities are integers in the drug's base `unit` (sachets, tablets, vials, and so on).
    - IDs: state `TN`, district `TN-D01`, facility `TN-PHC-014`, drug code `ORS`.
    - Numbers come from models and SQL. Gemini text fields (`reason`, `answer`) only explain supplied facts.
    - Every error uses the `Error` envelope. Validation failures are HTTP 422.
    - When the server runs with `MOCK_MODE=true`, every response carries the header `X-Mock: true`
      and returns the fixtures generated from the examples in this file.

    ## Access (prototype)
    A role switcher in the frontend sends three headers on every call. Row filtering by role and
    district is enforced in SQL on the backend. Real Firebase auth is design-only for the prototype.

    | Header | Values |
    |---|---|
    | `X-Role` | `FACILITY`, `BLOCK`, `DISTRICT`, `STATE`, `AUDITOR` |
    | `X-District` | a district id, or `ALL` for `STATE` and `AUDITOR` |
    | `X-User` | user id, written to the audit log |

    `AUDITOR` is read-only: any write returns 403.

    ### Default permissions (proposed; enforce in one middleware)
    `own` means the caller's facility, block or district.

    | Action | FACILITY | BLOCK | DISTRICT | STATE | AUDITOR |
    |---|---|---|---|---|---|
    | Read facilities, status, forecast, risk, transfers, alerts | own facility | own block | own district | all | all |
    | Capture (voice, photo, confirm) | own facility | own block | own district | yes | no |
    | `POST /optimize` | no | own block | own district | yes | no |
    | Transfer decision | no | own block | own district | yes | no |
    | `POST /copilot/ask` | yes | yes | yes | yes | yes |
    | `POST /scenario/run` | no | no | own district | yes | no |
    | `POST /federation/round` | no | no | no | yes | no |
    | `GET /federation/rounds` | no | no | no | yes | yes |
    | `GET /audit` | no | no | own district | yes | yes |

    ## Key flows
    - **Capture:** `POST /capture/voice` returns rows. Rows with `needs_confirm=true` must be confirmed
      by the user. `POST /capture/confirm` saves them and returns `updated_status` so the map refreshes.
    - **Redistribution:** `POST /optimize` returns proposals (state `OPEN`), then the user calls
      `POST /transfers/{id}/decision`.
    - **Copilot refusals** are HTTP 200 with `refused: true`, not errors.

    ## Frontend notes
    - `route.polyline` is a Google encoded polyline (decode with the Maps JS geometry library).
    - `GET /risk` returns AMBER and RED only unless `status` is passed. Use `GET /facilities` for map markers.
    - `/forecast` points are daily; `history` is the last 28 days of actuals.
    - In `/federation/rounds`, plot `local_only_mape` against `federated_mape` per state. The state with
      `is_data_sparse: true` shows the biggest drop in the demo.

    ## Errors and suggested UI behaviour
    `forbidden` 403 hide the action. `not_found` 404 empty state. `invalid_transition` 409 refresh the
    transfer. `file_too_large` 413 ask to record or shoot again. `validation_error`,
    `constraint_violation`, `unparseable_scenario` 422 show `message`. `upstream_unavailable` 502 show retry.

  /copilot/ask:
    post:
      tags: [copilot]
      operationId: askCopilot
      summary: Natural-language question over approved views
      description: |
        Gemini selects an approved query template or view, the SQL runs read-only with role and
        district filters applied in SQL, and Gemini summarises the returned rows. Out-of-scope
